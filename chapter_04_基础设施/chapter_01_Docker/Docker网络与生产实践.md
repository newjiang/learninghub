# Docker 网络与生产实践

> 阅读定位：本篇是导读与速查，不代替深入正文。已展开专题和当前覆盖边界见[知识手册导航](../../知识手册导航.md)。

适用范围：Linux Docker Engine、BuildKit 和 Compose v2。Windows/macOS 桌面通常经 Linux 虚拟机运行容器，网络路径与原生 Linux 不完全相同。配合现有安装、命令及存储笔记使用。

## 1. 隔离、资源与镜像

namespace 提供进程、网络等视图隔离，cgroup 管资源，镜像分层与可写层提供文件系统组合。容器共享宿主内核，不等于虚拟机的独立内核隔离；镜像小也不等于运行内存小。

构建按变化频率排列层，先复制依赖描述再复制源码以复用缓存；多阶段构建将编译工具留在构建阶段。生产镜像锁定 digest，通过流水线更新和扫描。build ARG/ENV 不适合保存密钥，使用构建秘密挂载并验证产物不含秘密。

```dockerfile
# 示例：先由独立构建流程产出 app.jar；上线时固定基础镜像 digest。
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --chown=10001:10001 app.jar app.jar
USER 10001:10001
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
```

exec 形式使 Java 直接接收容器信号。应用写入目录需显式挂载和赋权；只读根文件系统部署要为临时目录提供独立空间。JVM 除堆还占用 metaspace、线程栈、direct buffer 等，堆不能等于容器内存上限。

## 2. 网络路径与服务发现

默认 bridge 与用户自定义 bridge 能力不同；Compose 网络中的服务通常通过服务名发现。`localhost` 指当前网络命名空间，容器内访问 localhost 不等于访问宿主机或其他容器。

发布端口建立宿主到容器的访问路径，应用应监听适当地址而不只监听容器内 127.0.0.1。EXPOSE 是元信息，不自动发布端口。容器间通信优先使用私有网络和服务名，不要硬编码会变化的容器 IP。

排查按“进程是否监听 → 容器内地址 → 同网络服务名解析 → 容器间 TCP → 宿主发布端口 → 防火墙/外部入口”逐层进行，避免一开始就用 host 网络绕过问题。

## 3. 数据与生命周期

可写层随容器替换丢失，持久数据用 volume 或受控 bind mount；挂载不是备份，宿主故障和误写仍会传播。数据库备份需要数据库一致性协议，不能随意复制正在写入的数据目录。

容器启动不等于应用就绪，Compose 依赖启动顺序不自动保证业务可用。应用本身要对依赖连接失败有限重试，配合健康检查。优雅停止包含信号处理、停止接流、等待在途任务和截止后退出。

## 4. 故障与面试

| 现象 | 证据 | 判断 |
| --- | --- | --- |
| 容器退出 137 | OOMKilled、宿主日志、事件 | 可能是强杀，不能只凭退出码认定 OOM |
| 磁盘越来越满 | 镜像层、日志、volume 使用 | 建立日志轮转，先确认再清理 |
| 镜像能启动但接口不通 | 监听地址、端口映射、网络 | 区分进程健康和网络可达 |
| 权限错误 | UID/GID、挂载目录、只读标记 | 避免用 privileged 掩盖配置问题 |

- **容器为什么不是安全沙箱的完整替代？** 共享内核，权限、capability、seccomp 和宿主配置都影响隔离。
- **练习**：两个服务组成私有网络，仅发布入口端口，替换容器并验证 volume 数据。验收：非 root 运行，信号可达，日志有轮转策略，无秘密进入镜像层。
