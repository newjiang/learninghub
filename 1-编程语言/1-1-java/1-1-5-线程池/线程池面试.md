<a id="q-01"></a>
### Q1：任务提交后先加线程还是先入队？

> **一句话结论**：小于 core 先建线程，否则先入队，放不下才尝试扩到 max。

**机制展开**：入队成功后还需重检运行状态与 worker 数，防止 shutdown 竞争与队列无人消费。

**⚖️ 方案对比与代价**：队列大小直接改变扩容时机，无界队列常令 max 失效。

**🔎 追问演练**：core=2、max=4、队列=2，七个阻塞任务怎样分布？

**推演要点**：前两运行、接着两排队、再两运行、第七拒绝；先提交不保证先完成。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-02)。

<a id="q-02"></a>
### Q2：如何给线程池定容量？

> **一句话结论**：从处理器、下游资源、排队期限和内存预算推导，再压测。

**机制展开**：平均在途量可用 L=λW 理解，但峰值、长尾和重试会改变实际压力。

**⚖️ 方案对比与代价**：队列太小增加拒绝，太大隐藏过载；线程增加也可能只增加连接等待。

**🔎 追问演练**：CPU 空闲但请求很慢应加线程吗？

**推演要点**：先定位等待连接、远端、锁还是排队；如果下游已满，加线程只增加等待者。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-03)。

<a id="q-03"></a>
### Q3：CallerRunsPolicy 一定安全吗？

> **一句话结论**：它提供特定反馈，但会改变调用线程的工作与延迟，关闭后还会丢弃。

**机制展开**：未关闭时提交线程同步执行任务，可能阻塞请求或事件循环；上下文和事务边界也可能改变。

**⚖️ 方案对比与代价**：可用于有意设计的背压，不适合无条件兜底；明确拒绝通常更易观测。

**🔎 追问演练**：submit 搭配静默丢弃为何 get 一直等？

**推演要点**：FutureTask 未执行也未被取消，没有进入终态；拒绝策略要抛错或明确完成/取消。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-04)。

<a id="q-04"></a>
### Q4：execute 与 submit 的异常有什么不同？

> **一句话结论**：execute 的未捕获异常与 submit 保存到 Future 的异常有不同观察入口。

**机制展开**：FutureTask 捕获失败，get 抛 ExecutionException；afterExecute 的异常参数可能仍为 null。

**⚖️ 方案对比与代价**：只记录线程未捕获异常处理器会漏掉 submit 失败，须集中观察结果。

**🔎 追问演练**：池线程没死是否说明任务成功？

**推演要点**：不说明，失败可能被结果对象存储；检查完成结果而非线程存活。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-05)。

<a id="q-05"></a>
### Q5：get 超时或 cancel(true) 会停止任务吗？

> **一句话结论**：等待超时不停止任务，取消中断也只是协作请求。

**机制展开**：阻塞 API 是否响应中断、任务是否检查状态、远端操作是否已发生都决定实际效果。

**⚖️ 方案对比与代价**：需要总期限、底层超时、退出清理与幂等协议，不能依赖强杀。

**🔎 追问演练**：超时后重试为什么重复扣款？

**推演要点**：第一次可能已提交成功但响应丢失；线程池不解决跨系统结果不确定性。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-06)。

<a id="q-06"></a>
### Q6：shutdown 与 shutdownNow 的区别？

> **一句话结论**：前者停止接纳但处理队列，后者停止取队列并尝试中断运行任务。

**机制展开**：两者都不保证立即终止；shutdownNow 返回未执行任务，需要自行处理结果等待者。

**⚖️ 方案对比与代价**：优雅关闭有预算与升级策略，不能无限等待或无声丢任务。

**🔎 追问演练**：返回的 FutureTask 会自动取消吗？

**推演要点**：不能这样假定，移出队列与状态取消是不同操作，必须明确通知等待方。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-07)。

<a id="q-07"></a>
### Q7：周期任务为什么突然不执行了？

> **一句话结论**：未处理异常会抑制后续周期执行。

**机制展开**：调度线程仍可继续处理别的任务，异常保存在对应 Future；固定频率与固定延迟只影响计划，不改变失败规则。

**⚖️ 方案对比与代价**：预期失败可受控捕获继续，致命失败需告警与明确终止。

**🔎 追问演练**：一个周期任务很慢会自己并行重叠吗？

**推演要点**：ScheduledThreadPoolExecutor 不并发执行同一个周期任务；fixed rate 可能延后并追赶。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-08)。

<a id="q-08"></a>
### Q8：固定池为什么会线程饥饿死锁？

> **一句话结论**：父任务占满 worker 并等待同池子任务，子任务无执行者。

**机制展开**：队列有任务不代表能运行，依赖图与执行资源形成闭环。

**⚖️ 方案对比与代价**：异步组合或拆分执行资源可缓解，还要检查共享连接、锁等下游限制。

**🔎 追问演练**：把 max 调大一定解决吗？

**推演要点**：无界队列可能根本不扩容；资源闭环也可能仍存在，应修依赖协议。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-09)。

<a id="q-09"></a>
### Q9：ThreadLocal 在线程池里为什么污染？

> **一句话结论**：工作线程被复用，局部值会跨任务存活。

**机制展开**：提交线程设置值不会自动传播到既有 worker，InheritableThreadLocal 也只是在线程创建时继承。

**⚖️ 方案对比与代价**：装饰任务需捕获、安装并 finally 恢复/清理，避免泄漏敏感上下文与对象。

**🔎 追问演练**：CallerRuns 任务清理时能直接 remove 所有调用方值吗？

**推演要点**：不能无条件破坏调用方原上下文；要恢复进入前的值和作用域。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-09)。

<a id="q-10"></a>
### Q10：虚拟线程应该池化吗？

> **一句话结论**：通常每任务新建虚拟线程，以单独并发限制保护稀缺资源。

**机制展开**：虚拟线程在等待时可让出载体线程，但 CPU、连接数和下游吞吐仍受限。

**⚖️ 方案对比与代价**：平台线程池管理昂贵执行者，虚拟线程模型把资源预算移到准入与下游门控。

**🔎 追问演练**：一百万个等待连接的虚拟线程有问题吗？

**推演要点**：仍占内存和上下文，且可能早已超过期限；需要在进入前控制并发和排队。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-10)。

<a id="q-11"></a>
### Q11：为什么不建议只抄 Executors 工厂？

> **一句话结论**：每个工厂隐含了容量策略，应先知道这些策略是否符合负载。

**机制展开**：fixed 常配近乎无界队列，cached 常配直接交接并允许很多线程，不能只看方法名。

**⚖️ 方案对比与代价**：工厂并非天然错误；显式配置更便于表达预算，关键是认清上限。

**🔎 追问演练**：keepAliveTime 能限制慢任务执行多久吗？

**推演要点**：不能，它控制空闲线程回收；任务期限要另行实现。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-03)。

<a id="q-12"></a>
### Q12：如何判断线程池调优有效？

> **一句话结论**：看端到端延迟、成功完成率和资源稳定性，而非只看活跃线程数。

**机制展开**：区分排队耗时与运行耗时，记录拒绝、失败、取消及任务过期，检查下游压力。

**⚖️ 方案对比与代价**：吞吐上升却尾延迟和错误升高，可能是把压力转移给数据库。

**🔎 追问演练**：为什么队列变短但服务更慢？

**推演要点**：任务可能转到 CallerRuns 或下游等待；需跟踪完整调用链和在途量。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-10)。

<a id="q-13"></a>
### Q13：核心线程是一批永久固定的线程吗？

> **一句话结论**：不是，core 主要表达数量阈值，回收要看状态、配置与取任务逻辑。

**机制展开**：worker 执行 firstTask 后循环 getTask；允许核心超时、调整参数和关闭都影响退出。

**⚖️ 方案对比与代价**：复用节省创建成本，但任务间上下文必须清理，异常退出还需按池状态补充。

**🔎 追问演练**：submit 失败为什么 worker 没退出？

**推演要点**：FutureTask 已捕获业务异常，外层循环可能看到正常返回。

**原理展开**：[线程池原理对应章节](线程池原理.md#p-11)。

<a id="q-14"></a>
### Q14：工作窃取为什么从另一端取任务？

> **一句话结论**：它把拥有者的本地推进与其他线程领取分支分开，减少共同端的争用。

**机制展开**：默认模式较新任务本地优先、较老分支可窃取，另有外部提交与非默认模式规则。

**⚖️ 方案对比与代价**：适合可拆计算，不保证业务 FIFO，也不能消除外部资源等待。

**🔎 追问演练**：任务拆得越细越好吗？

**推演要点**：不是，分配、调度与合并成本需要计算粒度覆盖。

**原理展开**：[线程池深入机制](线程池原理.md#p-12)。

<a id="q-15"></a>
### Q15：fork 后为什么常直接 compute 另一支？

> **一句话结论**：当前线程继续推进并暴露一个可并行分支，减少无谓全部入队。

**机制展开**：最后 join 汇合结果，运行时能围绕自身任务依赖采取协作策略。

**⚖️ 方案对比与代价**：计算阈值和输入共享决定正确性与收益，不能将示例阈值当通用参数。

**🔎 追问演练**：join 能补偿所有 JDBC 阻塞吗？

**推演要点**：不能，外部阻塞与 fork/join 任务依赖不同，下游容量依然受限。

**原理展开**：[线程池深入机制](线程池原理.md#p-12)。

<a id="q-16"></a>
### Q16：多个阶段各设 1 秒超时为什么请求花了 3 秒？

> **一句话结论**：各阶段重复拿到了完整预算，没有共同截止时间。

**机制展开**：排队、连接和远端都应消耗剩余预算，并在开始执行前检查过期。

**⚖️ 方案对比与代价**：总期限使过载可控，但要打通底层取消与清理，Future 超时本身不够。

**🔎 追问演练**：排队任务已经超时还会写数据库吗？

**推演要点**：可能，需要明确过期检查、取消与移除协议，外部副作用还要幂等。

**原理展开**：[线程池深入机制](线程池原理.md#p-13)。

<a id="q-17"></a>
### Q17：分成两个线程池为何仍互相等待？

> **一句话结论**：线程隔离没有切断数据库连接、锁等共享资源依赖。

**机制展开**：父任务持有资源等待子任务，子任务又需要该资源，形成跨层等待环。

**⚖️ 方案对比与代价**：先修资源作用域与依赖图，再考虑容量；加线程不解决资源闭环。

**🔎 追问演练**：怎么证明瓶颈已从线程池转移到连接池？

**推演要点**：同时看排队与连接等待、在途量和资源持有时间，避免只看线程池队列。

**原理展开**：[线程池深入机制](线程池原理.md#p-13)。
