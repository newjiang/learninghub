### Q1：JDBC、驱动与连接池分别做什么？

> **一句话结论**：JDBC 定义访问契约，驱动实现数据库协议，池复用并限制连接资源。

**机制展开**：DataSource 是连接来源抽象不必然池化，JDBC 4 起常规环境可自动发现驱动。

**⚖️ 方案对比与代价**：统一接口减少耦合，但数据库和可选能力仍不同。

**🔎 追问演练**：为什么新项目还可能需要排查驱动加载？

**推演要点**：服务发现受加载器与打包可见性影响，不代表 API 自动发现绝不失败。

**原理展开**：[JDBC原理对应章节](JDBC原理.md#p-01)。

<a id="q-02"></a>
### Q2：close 连接会断开数据库吗？

> **一句话结论**：直接连接常关闭物理会话，池代理通常归还借用句柄。

**机制展开**：物理会话状态继续存在，需要重置或销毁失效连接；不要跨请求共享借用连接。

**⚖️ 方案对比与代价**：池减少建连成本却引入状态与排队管理，最大连接数不是越大越好。

**🔎 追问演练**：readOnly 或 schema 会污染下一个请求吗？

**推演要点**：取决于池与应用重置契约，尤其自定义会话变量不能假定全部清理。

**原理展开**：[JDBC原理对应章节](JDBC原理.md#p-02)。

<a id="q-03"></a>
### Q3：PreparedStatement 防注入和预编译是一回事吗？

> **一句话结论**：不是，绑定值的安全边界与服务端计划复用是两件事。

**机制展开**：数据不按 SQL 结构解释，但是否服务端预编译受驱动和配置影响。

**⚖️ 方案对比与代价**：动态表名与排序方向不能直接绑定，应用白名单构造；LIKE 通配也要单独处理。

**🔎 追问演练**：为什么问号不能替代 ORDER BY 列名？

**推演要点**：那是语法标识符位置，绑定参数通常表达数据值。

**原理展开**：[JDBC原理对应章节](JDBC原理.md#p-03)。

<a id="q-04"></a>
### Q4：setAutoCommit(true) 能当清理用吗？

> **一句话结论**：不能随意使用，切换到自动提交可能提交当前事务。

**机制展开**：关闭自动提交后应明确 commit/rollback，活动事务直接 close 也有实现相关性。

**⚖️ 方案对比与代价**：把恢复放在事务完成后并核对池契约，失败连接需正确淘汰。

**🔎 追问演练**：catch 后没 rollback 就归还会怎样？

**推演要点**：可能留下活动事务和锁，或被实现以不同方式处理；不能依赖猜测。

**原理展开**：[JDBC原理对应章节](JDBC原理.md#p-04)。

<a id="q-05"></a>
### Q5：JDBC 如何避免转账半成功？

> **一句话结论**：在同一连接事务内检查原子条件更新与影响行数，失败则回滚。

**机制展开**：先查余额再无条件更新会竞争；扣款条件应进 SQL，收款不存在也要判失败。

**⚖️ 方案对比与代价**：本地原子性不解决幂等与提交响应丢失，死锁还需有限事务级重试。

**🔎 追问演练**：commit 抛异常能直接重做吗？

**推演要点**：结果可能已提交但响应丢失，先按业务标识确认或走幂等恢复。

**原理展开**：[JDBC原理对应章节](JDBC原理.md#p-05)。

<a id="q-06"></a>
### Q6：getInt 读到零怎样辨别 NULL？

> **一句话结论**：紧接 wasNull 或按支持情况用包装类型 getObject。

**机制展开**：原始类型无法表示 null，结果集还受游标和资源生命周期限制。

**⚖️ 方案对比与代价**：显式映射比依赖隐式转换稳妥，金额与时间要定义精度和时区语义。

**🔎 追问演练**：能从关闭连接的方法返回 ResultSet 吗？

**推演要点**：通常不行，结果依赖 Statement/Connection，应在作用域内消费或映射为独立数据。

**原理展开**：[JDBC原理对应章节](JDBC原理.md#p-06)。

<a id="q-07"></a>
### Q7：fetchSize 就是流式开关吗？

> **一句话结论**：不是，接口提示与驱动真正分批或游标行为有区别。

**机制展开**：不同驱动还要求事务、结果类型、连接参数等前提，客户端 collect 仍可积累全量。

**⚖️ 方案对比与代价**：游标降低部分缓存却延长连接与快照占用，分页又有一致性与断点权衡。

**🔎 追问演练**：逐行读为什么内存仍增长？

**推演要点**：检查驱动是否全量缓冲、应用是否持有所有行、LOB 和缓存是否释放。

**原理展开**：[JDBC原理对应章节](JDBC原理.md#p-07)。

<a id="q-08"></a>
### Q8：executeBatch 报错会自动全回滚吗？

> **一句话结论**：不能假定，要看事务边界和驱动部分执行规则。

**机制展开**：异常含部分更新计数，SUCCESS_NO_INFO 与 EXECUTE_FAILED 含义不同。

**⚖️ 方案对比与代价**：显式事务可设计整批回滚，大批次却增加锁、日志与恢复成本。

**🔎 追问演练**：能由首个自增键推算全批键吗？

**推演要点**：不能作为通用保证，应核对生成键支持与映射，最好有可追踪业务标识。

**原理展开**：[JDBC原理对应章节](JDBC原理.md#p-08)。

<a id="q-09"></a>
### Q9：JDBC 超时等于事务已回滚吗？

> **一句话结论**：不等于，超时和 cancel 的实际效果取决于阶段与实现。

**机制展开**：连接获取、建连、查询、网络和提交有不同预算，执行结果还可能不确定。

**⚖️ 方案对比与代价**：总期限需分配给各阶段，失败按数据库码与连接状态分类。

**🔎 追问演练**：什么错误适合重试？

**推演要点**：如死锁冲突可有限重试完整事务，语法认证与业务约束通常要先修因。

**原理展开**：[JDBC原理对应章节](JDBC原理.md#p-09)。

<a id="q-10"></a>
### Q10：Spring 事务里新开 JDBC 连接会参与吗？

> **一句话结论**：通常不会自动加入原本的本地事务。

**机制展开**：框架将连接与当前事务关联，直接新建连接、换线程或换数据源可能绕过该关联。

**⚖️ 方案对比与代价**：使用框架的事务参与接口，别混淆方法注解与物理连接边界。

**🔎 追问演练**：Savepoint 是否就是 REQUIRES_NEW？

**推演要点**：不是，前者在同一事务回退，后者是框架的新事务语义。

**原理展开**：[JDBC原理对应章节](JDBC原理.md#p-10)。

<a id="q-11"></a>
### Q11：连接校验成功为什么下一条 SQL 仍会断线？

> **一句话结论**：探测只反映当时状态，校验与使用之间仍有故障窗口。

**机制展开**：连接借出、探测、执行和提交分别涉及时间与协议，池不能承诺未来网络一直正常。

**⚖️ 方案对比与代价**：校验降低坏连接概率但有成本，仍须对执行失败做分类和资源淘汰。

**🔎 追问演练**：提高 validation timeout 能解决长 SQL 吗？

**推演要点**：不能混用参数，它控制探测，不是业务执行预算。

**原理展开**：[JDBC深入机制](JDBC原理.md#p-11)。

<a id="q-12"></a>
### Q12：连接池为什么无法重置所有会话状态？

> **一句话结论**：通用代理不一定理解专有 SET SQL、临时表和自定义角色操作。

**机制展开**：标准 setter 较易跟踪，专有状态要有明确恢复或连接专属策略；重置失败需考虑淘汰。

**⚖️ 方案对比与代价**：复用减少建连成本，却要求隔离借用者状态，不能把 close 当全部清理证明。

**🔎 追问演练**：任意 SQLException 都该销毁物理连接吗？

**推演要点**：不应，业务约束错误和网络协议失效有不同健康含义。

**原理展开**：[JDBC深入机制](JDBC原理.md#p-11)。

<a id="q-13"></a>
### Q13：事务冲突为什么要重试整个事务？

> **一句话结论**：新的并发状态可能改变先前读取与业务决策，只重放最后 SQL 不再等价。

**机制展开**：明确中止后释放旧资源，重新建立事务并读取，按数据库错误类别与剩余期限有限重试。

**⚖️ 方案对比与代价**：死锁、锁超时、约束冲突和提交断线恢复不同，不能只看一个 transient 类名。

**🔎 追问演练**：锁等待超时一定整笔自动回滚吗？

**推演要点**：不能跨数据库泛化，核实回滚范围并明确结束旧事务。

**原理展开**：[JDBC深入机制](JDBC原理.md#p-12)。

<a id="q-14"></a>
### Q14：commit 抛异常为什么不能立即重做扣款？

> **一句话结论**：可能数据库已提交而响应丢失，直接重做会重复副作用。

**机制展开**：用稳定幂等标识与同库原子记录协调恢复，权威查询和唯一约束处理未决事务。

**⚖️ 方案对比与代价**：结果记录有保留成本，外部系统副作用还需单独协议，不能承诺本地表包办全部。

**🔎 追问演练**：从副本查不到就能认定没提交吗？

**推演要点**：不能，复制延迟可隐藏成功结果，应使用满足一致性要求的确认路径。

**原理展开**：[JDBC深入机制](JDBC原理.md#p-12)。
