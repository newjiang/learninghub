### Q1：JDK 动态代理如何工作？

> **一句话结论**：生成实现接口的代理类，把调用分派给 InvocationHandler。

**机制展开**：handler 得到代理、Method 与参数，可转发本地目标，也可解释为远程或 SQL 协议。

**⚖️ 方案对比与代价**：接口类型清晰但不能直接当目标具体类，生成也受加载器可见性约束。

**🔎 追问演练**：MyBatis 接口没有实现类为什么能调用？

**推演要点**：handler 解释方法与映射，真正执行数据库协议，不必先找到手写实现类。

**原理展开**：[动态代理原理对应章节](动态代理原理.md#p-02)。

<a id="q-02"></a>
### Q2：为什么 method.invoke(proxy,args) 会递归？

> **一句话结论**：proxy 是代理入口，对它再次调用会重新进入 handler。

**机制展开**：正常转发应调用实际 target，默认方法则用对应机制。

**⚖️ 方案对比与代价**：处理器中打印 proxy 也可能触发 toString 递归，日志应选稳定标识。

**🔎 追问演练**：如何区分 target 和 proxy？

**推演要点**：记录对象身份与类，画出调用边；不要只看它们实现相同接口。

**原理展开**：[动态代理原理对应章节](动态代理原理.md#p-03)。

<a id="q-03"></a>
### Q3：UndeclaredThrowableException 从哪里来？

> **一句话结论**：处理器抛出的受检异常不符合接口声明时可能被包装。

**机制展开**：反射转发如果没解包 InvocationTargetException，会把基础包装层错当业务异常抛出。

**⚖️ 方案对比与代价**：正确传播需遵守接口与重复签名的异常契约，不能随便吞异常。

**🔎 追问演练**：业务 IOException 已声明为何仍被包装？

**推演要点**：先看 handler 抛的是 IOException 本身，还是包着它的 InvocationTargetException。

**原理展开**：[动态代理原理对应章节](动态代理原理.md#p-04)。

<a id="q-04"></a>
### Q4：接口 default 方法会自动执行吗？

> **一句话结论**：代理调用仍会到 handler，需要按策略显式转发默认实现。

**机制展开**：JDK 16 起 invokeDefault 提供相应入口，来源与覆盖规则仍需满足。

**⚖️ 方案对比与代价**：默认实现可减少本地重复，但不能通过再次调用 proxy 来绕过 handler。

**🔎 追问演练**：多个接口重复方法能按调用方类型辨别吗？

**推演要点**：不能简单假定，Method 来源受代理接口顺序与规则影响，注册时要解决冲突。

**原理展开**：[动态代理原理对应章节](动态代理原理.md#p-04)。

<a id="q-05"></a>
### Q5：JDK 与子类代理怎样选？

> **一句话结论**：看对外契约、继承限制、框架行为与访问条件，不按固定性能排名。

**机制展开**：前者实现接口，后者覆写可继承方法；final/private/static 对后者有边界。

**⚖️ 方案对比与代价**：子类形态支持目标类型，但生成和实例化更复杂，工具版本与模块也相关。

**🔎 追问演练**：final 实现类能被 JDK 代理吗？

**推演要点**：能通过它实现的接口委托；代理不是这个 final 类的子类。

**原理展开**：[动态代理原理对应章节](动态代理原理.md#p-05)。

<a id="q-06"></a>
### Q6：为什么自调用绕过事务代理？

> **一句话结论**：常见委托模型中 target.this 调用仍留在目标内部。

**机制展开**：外部进入代理再转 target.a，a 调 b 没有再经过代理入口。

**⚖️ 方案对比与代价**：拆到协作组件通常更清晰，自代理耦合或织入要有明确收益。

**🔎 追问演练**：换 CGLIB 一定解决吗？

**推演要点**：不能，先区分纯子类虚调用和框架独立目标委托模型。

**原理展开**：[动态代理原理对应章节](动态代理原理.md#p-06)。

<a id="q-07"></a>
### Q7：代理 equals/hashCode 应怎样做？

> **一句话结论**：必须明确身份与相等策略，保证契约一致，而不是随便全委托。

**机制展开**：Object 的相关方法也可到 handler，代理与目标互相比可能破坏对称性。

**⚖️ 方案对比与代价**：引用身份简单稳定，透明目标相等则需同时考虑集合键、多个代理和目标。

**🔎 追问演练**：为什么 Map 中代理键取不出？

**推演要点**：检查 equals/hashCode 是否一致、是否递归以及目标状态是否影响哈希。

**原理展开**：[动态代理原理对应章节](动态代理原理.md#p-03)。

<a id="q-08"></a>
### Q8：重试与事务的顺序重要吗？

> **一句话结论**：重要，它决定每次尝试是否落在独立事务边界。

**机制展开**：外层重试包事务与外层事务包重试具有不同进入退出次序，失败事务可能已不可继续。

**⚖️ 方案对比与代价**：还要结合传播、异常规则与幂等性，不能按注解源码顺序猜。

**🔎 追问演练**：返回 Future 后日志就记录成功合理吗？

**推演要点**：只说明方法返回，异步计算可能稍后失败；需定义观察的是提交还是完成。

**原理展开**：[动态代理原理对应章节](动态代理原理.md#p-07)。

<a id="q-09"></a>
### Q9：代理为什么出现同名接口不可见？

> **一句话结论**：类身份包含定义加载器，代理所用加载器必须看见正确接口身份。

**机制展开**：模块、非 public 接口包规则和签名中的依赖都会影响生成。

**⚖️ 方案对比与代价**：共享接口放公共加载域，插件内部实现隔离，缓存也要带身份。

**🔎 追问演练**：硬编码 $Proxy0 能稳定定位吗？

**推演要点**：不能，名称和位置不是稳定业务契约。

**原理展开**：[动态代理原理对应章节](动态代理原理.md#p-08)。

<a id="q-10"></a>
### Q10：验证动态代理应覆盖什么？

> **一句话结论**：除了普通返回，还要覆盖异常、Object 方法、默认方法、内部调用与异步完成。

**机制展开**：各项涉及不同适配和执行入口，正常接口调用通过并不证明整个代理正确。

**⚖️ 方案对比与代价**：技术选型应服务协议完整性，性能再以真实调用链验证。

**🔎 追问演练**：哪些场景直接静态包装更合适？

**推演要点**：接口少而稳定、希望编译期检查和清晰调试时，动态生成的收益可能不够。

**原理展开**：[动态代理原理对应章节](动态代理原理.md#p-09)。

<a id="q-11"></a>
### Q11：为什么重试与事务交换顺序会改变结果？

> **一句话结论**：外层控制重入，决定每次重试是进入新边界还是留在同一个边界。

**机制展开**：嵌套进入和退出顺序对应资源获取、回滚与清理；真实失败事务可能已经不可继续。

**⚖️ 方案对比与代价**：每次独立事务有开销，却更便于定义重试；仍需有限次数、总期限和幂等。

**🔎 追问演练**：调用对象带可变拦截器下标能直接重复 proceed 吗？

**推演要点**：不一定，可能跳过已走过的增强，必须按框架重入或克隆契约处理。

**原理展开**：[动态代理深入机制](动态代理原理.md#p-10)。

<a id="q-12"></a>
### Q12：缓存增强放在权限增强外层有何风险？

> **一句话结论**：缓存命中可能直接返回，跳过本应执行的权限检查。

**机制展开**：短路层不调用 next 时内层均不运行，顺序因此影响安全和观测。

**⚖️ 方案对比与代价**：不能只看每个增强单独正确，要验证命中、失败与短路的组合路径。

**🔎 追问演练**：一个请求重试三次应记一次还是三次指标？

**推演要点**：区分请求与尝试两套指标，外内层放置对应不同统计含义。

**原理展开**：[动态代理深入机制](动态代理原理.md#p-10)。

<a id="q-13"></a>
### Q13：代理收到的 Method 声明 IOException 就能直接抛它吗？

> **一句话结论**：若多个接口重叠同签名，还必须满足其他声明的异常约束。

**机制展开**：Method 来源与整个代理方法合法异常集合不是同一件事，违反约束可被包装为 UndeclaredThrowableException。

**⚖️ 方案对比与代价**：注册时消歧优于调用时才发现，接口顺序不能绕开所有异常限制。

**🔎 追问演练**：A 抛 IO、B 抛 SQL 的同签名能只按 A 的 throws 转发吗？

**推演要点**：不能忽略 B 的契约，需要检查共同兼容的受检异常。

**原理展开**：[动态代理深入机制](动态代理原理.md#p-11)。

<a id="q-14"></a>
### Q14：代理 finally 能代表异步业务完成吗？

> **一句话结论**：不能，它通常只标记同步入口返回或抛错。

**机制展开**：阶段对象返回后工作可继续，完成观察器又可能在其他线程运行，并产生新的结果阶段。

**⚖️ 方案对比与代价**：计时、事务、上下文和资源清理要绑定各自真实生命周期。

**🔎 追问演练**：whenComplete 回调失败会改写 original 吗？

**推演要点**：不会回写已完成 original，但可能让其返回的 observed 阶段失败。

**原理展开**：[动态代理深入机制](动态代理原理.md#p-11)。
