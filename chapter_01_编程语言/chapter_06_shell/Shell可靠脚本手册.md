# Shell 可靠脚本导读与速查

> 阅读定位：本篇是导读与速查，不代替深入正文。已展开专题和当前覆盖边界见[知识手册导航](../../知识手册导航.md)。

适用范围：Linux Bash 5.x，不能直接当作 POSIX sh 或 PowerShell。脚本负责可解释的自动化；复杂状态机和数据模型应转用通用语言。

## 1. 展开、引用与退出状态

Shell 先解析语法再执行多种展开。未引用的变量展开可能经历分词和通配符展开，路径中空格、星号或前导减号会造成意外。参数用数组，变量用双引号，命令参数边界用 `--`（前提是该命令支持）。不要用 `eval` 执行拼接的用户输入。

`set -e` 有条件语句、逻辑列表等例外，不是完整异常系统；`pipefail` 可以让管道中非最后一项的失败反映到状态中。重要步骤显式检查，并定义失败时是否可重试、是否需人工处理。

```bash
#!/usr/bin/env bash
set -euo pipefail

input=${1:?usage: report.sh INPUT}
[[ -f "$input" ]] || { echo 'input is not a file' >&2; exit 2; }
scratch=$(mktemp)
trap 'rm -f -- "$scratch"' EXIT
# 示例仅在临时文件中工作，不修改输入。
LC_ALL=C sort -- "$input" > "$scratch"
wc -l < "$scratch"
```

`$(...)` 去掉末尾换行，不适合精确保留任意二进制内容。`for f in $(ls)` 会破坏包含空白的文件名；需要递归文件流时使用 `find ... -print0` 配合读 NUL 分隔的工具。

## 2. 管道、信号与幂等

管道中的命令可能在子 shell 中运行，其中设置的变量不一定保留在父 shell。`trap` 负责清理临时资源，但 SIGKILL 无法被捕获；因此重要状态还要支持重启恢复。后台任务需要记录 PID、等待并汇总失败，不能仅启动后立即报告成功。

发布脚本先写入临时目录，验证文件完整性，再在同一文件系统内通过重命名切换路径。重命名能提供目录项层面的原子替换，但不自动提供掉电持久性，也不能替代数据库事务。多机并发执行应由部署平台协调，单机 `flock` 只能处理其锁作用域内的竞争。

## 3. 工作速查

| 需求 | 处理方式 | 验证点 |
| --- | --- | --- |
| 检查脚本语法 | `bash -n script.sh` | 不执行脚本，不能发现所有运行错误 |
| 静态检查 | ShellCheck | 指定 Bash 方言并审查豁免 |
| 调试 | 有选择地开启 xtrace | 密钥参数及令牌不得进入输出 |
| 文本筛选 | rg / awk | 明确字符集、字段分隔及正则含义 |
| 重复运行 | 先查状态再变更，结果可复用 | 并发场景还需锁或原子操作 |

外部命令设超时，网络调用明确退出状态、HTTP 状态和输出文件校验。重试前判定操作是否幂等；“超时”不能证明服务端未处理。

## 4. 排查与面试

- **命令手工成功，CI 失败？** 比较执行用户、工作目录、PATH、Shell、换行符、权限和交互环境，避免把登录配置当隐式依赖。
- **为什么 `"$@"` 重要？** 保留每个原始参数边界；`$*` 或未引用展开会改变参数结构。
- **如何处理半成功？** 记录每个步骤的结果，使用可续跑状态或补偿；不要简单重新执行全部步骤。
- **如何防止误删？** 先解析并校验绝对目标在允许根目录内，拒绝空路径和根路径，提供可审查的目标清单；本章示例只清理 mktemp 创建的文件。

## 5. 练习与验收

做一个只读日志统计脚本，支持带空格的路径、不存在的输入和空文件。验收：输入不被修改，错误写 stderr 并返回非零，执行中断能清理临时文件，文件名包含通配符时结果仍正确。
